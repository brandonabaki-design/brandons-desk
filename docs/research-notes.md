# Research notes (verified 2026-10-10)

Facts the implementation relies on. "Verified" means read in official docs, the API discovery document, or the clasp source; "reported" means consistent community reports. Raw research JSON lives outside the repo.

## clasp 3.4.1 (verified against `clasp --help` in this sandbox and the clasp README/releases)

- Requires Node ≥ 22. Install: `npm install -g @google/clasp`. Per-user toggle "Google Apps Script API" at https://script.google.com/home/usersettings is still required; without it: "User has not enabled the Apps Script API…".
- Command names changed in v3 (old names still work as aliases for most): `create-script` (alias `create`), `clone-script`, `push`, `pull`, `create-deployment` (alias `deploy`), `update-deployment <id>` (alias `redeploy`; replaces v2 `deploy -i`), `list-deployments`, `create-version`, `list-versions`, `open-script` (v2 `open`), `open-web-app [deploymentId]`, `run-function` (alias `run`), `show-authorized-user`.
- `clasp create-script --type webapp --title "Brandon's Desk" --rootDir ./apps-script` creates a standalone script and writes `./.clasp.json` (`{"scriptId": "...", "rootDir": "./apps-script"}`) in the current directory, not inside rootDir. `--type webapp` is an alias for standalone that prints a deployment tip. It may pull a stub `Code.gs`/`appsscript.json` into rootDir.
- `.clasp.json` optional fields: `filePushOrder` (paths relative to the `.clasp.json` directory, so they include the rootDir prefix: `apps-script/Config.gs`), `scriptExtensions` (default `.js`, `.gs`), `htmlExtensions` (default `.html`). Files not in `filePushOrder` are pushed sorted by name. Apps Script loads every file into one global scope.
- Default `.claspignore`: only `appsscript.json` and `*.gs/*.js/*.ts/*.html` under rootDir are pushed; `node_modules/**` and `.git/**` ignored. clasp 3 does not transpile TypeScript.
- `clasp push` prompts when the manifest changed; `clasp push -f` overwrites without asking. `clasp push --watch` for development. The `/dev` URL runs the latest pushed code (owner only).
- Web-app deployments: clasp's deployment create/update sends no `entryPoints`, so a deployment made purely by clasp does not get "Execute as"/"Who has access" (clasp issues #63, #1115; PR #1173 unmerged as of 2026-10). Make the first web-app deployment in the editor (Deploy → New deployment → Web app → Execute as Me → Only myself), copy the `/exec` URL and Deployment ID. Later: `clasp push -f && clasp create-deployment -i <deploymentId> -d "..."` (or `clasp create-version` + `clasp update-deployment <id> -V <n>`); verify in Manage deployments (reported: sometimes needs the browser Edit → New version → Deploy).
- `clasp list-deployments` prints `- <deploymentId> @<version> - <description>` without the URL. URL = `https://script.google.com/macros/s/<deploymentId>/exec`.
- `clasp run-function` needs a standard GCP project, Desktop OAuth client and `executionApi` manifest entry — not worth it; press Run in the editor for `setup`.
- Keep the manifest `webapp` block anyway (the editor writes it; it documents intent): `{"webapp": {"executeAs": "USER_DEPLOYING", "access": "MYSELF"}}`.
- Never commit `.clasprc.json` or `client_secret.json`. `.clasp.json` holds only scriptId/rootDir (ignored in this repo so the user's ID stays local; it may be committed if they prefer).
- Workspace admins can turn Apps Script off per OU (Admin console → Apps → Google Workspace → Drive and Docs → Google Apps Script) and restrict OAuth scopes (Security → API controls). Symptom: authorisation fails or "This app is blocked". Nothing in code fixes that; the README names the admin setting.

## Triggers (verified)

- `ScriptApp.newTrigger('fn').timeBased().atHour(6).nearMinute(15).everyDays(1).inTimezone('Asia/Dubai').create()`; `inTimezone` takes IANA names; `atHour` fires within the hour unless `nearMinute` narrows it (±15 min). There is no weekday filter on time-based triggers: run daily and return early on Saturday/Sunday in code.
- Installable triggers run as, and are only visible to, the account that created them. Idempotent installer: `ScriptApp.getProjectTriggers().filter(t => t.getHandlerFunction() === 'captureInbox').forEach(t => ScriptApp.deleteTrigger(t))` then create.
- Quotas (reported from the quotas page): 20 triggers per user per script; trigger total runtime 6 h/day (Workspace); 6 min per execution; Gmail read/write 50 000/day (Workspace); URL Fetch 100 000/day.

## Gmail from Apps Script (verified)

- `GmailApp.search(query, start, max)` max 500 per call; use `GmailApp.getMessagesForThreads(threads)` to load all messages in one call. Each call that touches Gmail counts against the daily quota.
- `GmailThread.getId()` is documented as unstable ("varies based on the messages it contains"); `GmailMessage.getId()` is immutable. Dedupe key = `gmail:` + first message's id.
- `GmailMessage.getFrom()` returns `Name <addr>`; extract the address. "Me" = `Session.getEffectiveUser().getEmail()` + `GmailApp.getAliases()`.
- Detect already-handled threads: last message from me, or `msgs.some(m => m.isDraft())`.
- Bulk detection (community practice): `List-Unsubscribe`/`List-Id` headers (`msg.getHeader(name)`), `Precedence` bulk/list/junk, `Auto-Submitted` starting `auto-`, sender matching `/noreply|no-reply|donotreply|notifications?@|mailer-daemon|calendar-notification/i`.
- Official search operators: `to:me`, `from:me`, `newer_than:2d`, `category:promotions|social|forums|updates`, `in:inbox`, `is:chat` (Chat messages mirrored into Gmail), `rfc822msgid:`, `list:`, `has:nouserlabels`.
- Links: `GmailThread.getPermalink()` hard-codes `/u/0/#inbox/` (reported) — build links instead: `https://mail.google.com/mail/u/<email>/#all/<threadId>` (the `/u/<email>/` form redirects to the right account index; community pattern). The hex thread id after `#all/` opens the conversation reliably; a message id after `#all/` is reported to fail on cold loads. Durable per-message fallback: `https://mail.google.com/mail/u/<email>/#search/` + `encodeURIComponent('rfc822msgid:' + messageIdHeaderWithoutAngleBrackets)`; `msg.getHeader('Message-ID')` works in GmailApp.
- `Range.getValues()` returns `Date` objects for date cells and booleans for checkboxes; returning a `Date` from a `google.script.run` server function makes the call fail — serialise first.
- `Sheet.getDataRange().getValues()` reads a tab in one call; batch appends with `sheet.getRange(sheet.getLastRow()+1, 1, n, cols).setValues(rows)`; `appendRow` for single rows. Build an id→row map in memory; `createTextFinder(id).matchEntireCell(true)` for a single lookup.
- `LockService.getScriptLock().waitLock(ms)` throws on timeout; wrap in try/finally; keep Gmail fetching outside the locked section.
- Write `Date` objects (not strings) into date cells so they stay dates; the spreadsheet time zone (Asia/Dubai, already set) governs how they display; the script time zone comes from the manifest `timeZone`. `Utilities.formatDate(date, 'Asia/Dubai', 'yyyy-MM-dd')` for local dates. `Session.getScriptTimeZone()` reads the manifest zone.
- Checkbox cells: `getValues()` gives `true`/`false`; write booleans (a `'TRUE'` string violates the validation).

## Google Calendar (verified; used by the Claude routine, not by Apps Script capture)

- `CalendarEvent.getId()` returns the iCalUID, not the API event id. `htmlLink` comes from the Calendar advanced service (`Calendar.Events.list('primary', {...})`) and is account-agnostic — the safest link to store.

## Google Chat email notifications (reported; templates unverified)

- Sent from `chat-noreply@google.com` only for messages unread for more than ~12 hours, and by default only for DMs and @mentions (Chat settings → Notifications → Email). So the email fallback is delayed and partial; the parser must be defensive: search `from:chat-noreply@google.com newer_than:<n>d`, take the plain body, extract the first `https://chat.google.com/...` or `https://mail.google.com/chat/...` URL as the link, the subject as the space/sender hint, and the longest quoted paragraph as the text. Source key = `chat:email:<notification message id>`.

## Google Chat API from Apps Script with user auth (verified against the live discovery document, rev 2026-10-08)

- Since 17 July 2026 (Chat API release notes, GA), integrations that only READ on behalf of a user via OAuth no longer need a configured Chat app or a standard GCP project: enabling the API plus an OAuth client is enough. In Apps Script that means: declare the Chat advanced service in the manifest so the API is switched on in the script's default Cloud project, and declare the two read-only scopes explicitly. No `"chat": {}` key in the manifest (that registers the script as a Chat app).
  ```json
  "dependencies": {"enabledAdvancedServices": [{"userSymbol": "Chat", "serviceId": "chat", "version": "v1"}]},
  "oauthScopes": ["https://www.googleapis.com/auth/chat.spaces.readonly", "https://www.googleapis.com/auth/chat.messages.readonly", ...]
  ```
  The code calls the REST API with `UrlFetchApp` + `Authorization: Bearer ScriptApp.getOAuthToken()` + `muteHttpExceptions: true` (works for every method; the advanced `Chat` symbol is never referenced, so the code also loads when the service or scopes are removed).
- `GET https://chat.googleapis.com/v1/spaces?pageSize=100[&pageToken=]` lists spaces the caller is a member of (DMs and group chats appear once a first message exists). Space: `name` (`spaces/<id>`), `spaceType` (`SPACE` | `GROUP_CHAT` | `DIRECT_MESSAGE`), `displayName` (empty for DMs/group chats), `singleUserBotDm` (skip these), `lastActiveTime` (skip spaces with no activity in the lookback window), `spaceUri` (output-only user-facing link; prefer it).
- `GET https://chat.googleapis.com/v1/spaces/<id>/messages?pageSize=100&filter=<urlencoded create_time > "2026-10-08T02:15:00Z">[&pageToken=]` — filter grammar uses `create_time` with an RFC-3339 timestamp in double quotes; default order is oldest first; page while `nextPageToken`. Empty space returns `{}`. Message: `name` (`spaces/<id>/messages/<id>.<id>`, dotted), `sender` (`{name: "users/<id>", displayName, email, type: HUMAN|BOT}` — email populated under user auth for members), `createTime`, `text`, `formattedText`, `thread.name`, `threadReply`, `annotations[]` with `type: "USER_MENTION"` and `userMention.user.email`. Skip `sender.type === "BOT"`.
- Capture rule: DM or group-chat message not sent by me → candidate; SPACE message → candidate only when a `USER_MENTION` annotation names my email. Source key `chat:<message.name>`. Link = `space.spaceUri` when present, else `https://mail.google.com/chat/u/0/#chat/space/<spaceId>` (documented; still valid after Chat moved to chat.google.com). Message-level permalinks are undocumented, so they are not generated.
- Error shapes: HTTP 403 with `error.status = "PERMISSION_DENIED"` and `details[0].reason = "SERVICE_DISABLED"` (API not enabled in the script's project), `ACCESS_TOKEN_SCOPE_INSUFFICIENT` (token lacks the scopes, e.g. trigger installed before consent), 401 (no/invalid token). Treat any 401/403 as `CHAT_API_BLOCKED` → email mode. HTTP 429 is a quota blip: retry once after 2 s, then skip Chat for this run without switching modes. Quotas are per minute (3 000 message reads/min/project), so a daily scan is negligible.
- A Workspace admin can restrict the Chat scopes (they are Google "restricted" scopes) under Admin console → Security → Access and data control → API controls ("Trust internal apps", restricted services, Education high-risk scope list). That failure happens at CONSENT time for the whole project ("This app is blocked" or "Error 400: admin_policy_enforced"), not at runtime, and blocks Sheets and Gmail too. Remedy documented in the README: remove the two Chat scopes and the advanced service from `appsscript.json`, `clasp push -f`, re-authorise; Chat then runs in email mode.
- Triggers run with the installing user's granted scopes: run `installTriggers` AFTER the consent that included the Chat scopes.
- Email fallback (Google Help, verified): reminder emails are sent only for DMs and @mentions that stayed unread for more than 12 hours, and only when Chat → Settings → Notifications → Email notifications is "Only @mentions & direct messages" (not Off). Sender address `chat-noreply@google.com` and subject templates are NOT verified anywhere official; the parser must be tolerant (match the sender address or display name "Google Chat", any subject; take the first `https://chat.google.com/...` or `https://mail.google.com/chat/...` link from the body; use the subject as the From/space hint; the longest non-boilerplate paragraph as the text). The UI labels this mode as degraded.

## Apps Script web app facts (verified)

- Manifest `webapp` block has exactly `access` (`MYSELF` | `DOMAIN` | `ANYONE` | `ANYONE_ANONYMOUS`) and `executeAs` (`USER_ACCESSING` | `USER_DEPLOYING`). Top-level keys used: `timeZone`, `runtimeVersion: "V8"`, `exceptionLogging: "STACKDRIVER"`, `oauthScopes`, `dependencies`, `webapp`.
- Declaring `oauthScopes` turns scope auto-detection OFF: any service call outside the list fails at runtime with "You do not have permission to call …" / "Specified permissions are not sufficient". After changing the list, run any function from the editor to re-consent (triggers cannot prompt). Exact seven scopes for this project: `https://www.googleapis.com/auth/spreadsheets`, `https://www.googleapis.com/auth/gmail.readonly`, `https://www.googleapis.com/auth/script.external_request`, `https://www.googleapis.com/auth/script.scriptapp`, `https://www.googleapis.com/auth/userinfo.email`, `https://www.googleapis.com/auth/chat.spaces.readonly`, `https://www.googleapis.com/auth/chat.messages.readonly`. No Drive or Calendar scope (Calendar is read by Claude; the server-side xlsx export is not used).
- `GmailApp` read methods accept `gmail.readonly` (the runtime check is an OR-list: `https://mail.google.com/ || gmail.readonly || gmail.compose || gmail.modify`), even though the reference pages only list `https://mail.google.com/`. `selfTest()` proves it; if the error above ever appears after consent, the README says to replace `gmail.readonly` with `https://mail.google.com/`. `GmailApp.getAliases()` has no documented scope: call it in try/catch.
- With `executeAs: USER_DEPLOYING` + `access: MYSELF`, only the deploying account can open `/exec` (others get Google's generic "Sorry, unable to open the file at this time" page before `doGet` runs), and `Session.getActiveUser().getEmail()` returns the owner's email; `Session.getEffectiveUser()` is the owner. `guard()` accepts the active email, falling back to the effective email, and throws when neither is in `ALLOWED_EMAILS`.
- Multi-login is officially unsupported for web apps: when the browser's default Google account is not the deployer, `/exec` redirects to `/macros/u/N/…` and fails. Use a dedicated Chrome profile or incognito window signed in only as the work account; `?authuser=<email>` and `https://script.google.com/a/macros/aisa.sch.ae/s/<id>/exec` are unofficial nudges.
- HtmlService runs only the IFRAME sandbox on `*.googleusercontent.com`: HTTPS scripts/styles/fonts from any CDN load (no CSP allow-list to configure; HTTP is blocked as mixed content). Links out of the page need `target="_blank"` (or `_top`). A `<meta name="viewport">` written in the HTML file is stripped — call `.addMetaTag('viewport', 'width=device-width, initial-scale=1')` on the HtmlOutput. `setSandboxMode` is a no-op; `setXFrameOptionsMode` only matters for embedding (leave DEFAULT).
- Template include pattern: `function include(name) { return HtmlService.createHtmlOutputFromFile(name).getContent(); }` and `<?!= include('Styles') ?>` in `Index.html`; serve with `HtmlService.createTemplateFromFile('Index').evaluate().setTitle(...)`.
- `google.script.run`: parameters and return values may only be primitives, plain objects and arrays of them; a `Date`, function or DOM element anywhere (nested too) fails the call into `withFailureHandler` ("Failed due to illegal value"); `undefined` in arrays becomes `null`. At most 10 concurrent calls per page. Each call is one execution under the 6-minute cap (Workspace accounts too). No documented payload limit; tens of MB is the practical ceiling, so a to-do .html file passed as a string is fine.
- Downloads from the sandboxed iframe: `Blob` + `URL.createObjectURL` + `<a download>` click works on desktop browsers (`allow-downloads` is set); SheetJS `XLSX.writeFile` uses exactly that. iOS Safari may open the blob in a tab instead of saving: give the anchor `target="_blank"` and keep the CSV fallback. Revoke object URLs after ~1 s.
- SheetJS pinned URL, verified byte-for-byte via the cdnjs repository: `https://cdnjs.cloudflare.com/ajax/libs/xlsx/0.18.5/xlsx.full.min.js` (881 727 bytes), `integrity="sha384-vtjasyidUo0kW94K5MXDXntzOJpQgBKXmE7e2Ga4LG0skTTLeBi97eFAXsqewJjw" crossorigin="anonymous"`. npm/cdnjs are frozen at 0.18.5; it writes one-sheet workbooks with hyperlinks (`ws[addr].l = {Target: url}`) and column widths (`ws['!cols']`); cell styling (bold) is not in the community build.
- Time-driven triggers cannot select weekdays (`onWeekDay` only combines with `everyWeeks`): use one daily trigger (`everyDays(1).atHour(6).nearMinute(15).inTimezone('Asia/Dubai')`) and return early in `captureInbox()` when the Dubai ISO weekday is 6 or 7; `runCaptureNow()` bypasses that guard.
- `clasp create-script --rootDir ./apps-script` ALWAYS pulls a stub `Code.gs` and a default `appsscript.json` into rootDir, overwriting the committed manifest: run `rm apps-script/Code.gs && git checkout -- apps-script/appsscript.json` before `clasp push -f`. `filePushOrder` lives in `.clasp.json` (paths include the rootDir prefix).
- Apps Script became a Workspace core service in June 2026; the admin switch is Admin console → Apps → Google Workspace → Drive and Docs → Google Apps Script (on by default). The per-user "Google Apps Script API" toggle for clasp is separate.
- Quotas (Workspace): 6 min per execution, 6 h/day trigger runtime, 50 000 Gmail read/writes per day, 100 000 URL fetches per day, 20 triggers per user per script, 30 simultaneous executions. A daily 50-thread Gmail scan plus a few dozen Chat fetches is far below all of them.
