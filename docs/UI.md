# Web UI

Single page served by `doGet()` from `apps-script/Index.html` (template: `<?!= include('Styles') ?>` in the head, `<?!= include('App') ?>` at the end). No framework, no build step; plain ES2019 JavaScript (no optional chaining or nullish coalescing) so Apps Script V8, older Safari and the Node test harness all run it. DM Sans from Google Fonts with a system fallback; tokens on `:root` (accent `#21076C`, highlight `#D8B664`, backgrounds `#FFFFFF` / `#F7F6FB`) with a `prefers-color-scheme: dark` variant. Mobile first from 360 px with 16 px gutters; the Today page is two columns from 840 px.

## Components and conventions

- `api(name, payload)` is the only path to the server: a Promise around `google.script.run.withSuccessHandler().withFailureHandler()`. Every write shows a toast; failures show the server's message, roll back optimistic state and withdraw the optimistic success toast (tick, untick, drop). The first paint shows a loading state and keeps every page section hidden; a failed bootstrap shows only the error with Try again.
- Keyboard: opening the inline editor (Enter/click on a task title) moves focus into it; Save, Cancel and Escape return focus to the title; Move to the other list saves any unsaved editor edits first (one `updateTask`, then `moveTask`) and follows the task into its new column; Drop focuses the next task of the group (else quick-add) and sends only a note that was changed in the editor (the server appends notes); completing a task (Enter in the note box, Done, Done, no note) focuses the ticked row's checkbox when "Done today" is open (Space there is the keyboard undo), otherwise the next task of its group, otherwise quick-add; unticking and the toast's Undo focus the row's checkbox in its new group, also after the server reply re-renders the columns; Inbox Ignore focuses the next item's Promote button (else the status filter); History Reopen focuses the next item's Reopen button (else Apply); the promote form's Cancel returns to that item's Promote button; the agenda Move up / Move down / Remove buttons put focus back on the moved row's control after the sections re-render, so a keyboard or screen-reader user never drops to the top of the page. The editor's six fields are `<label for>`-named controls. The quick-add category toggle is a `radiogroup` with `role="radio"` / `aria-checked` buttons. The "Done today" group remembers that it was opened across re-renders (search, quick-add, toast-driven updates).
- Touch: the task checkbox, source-link icon, every `.btn.small` action button (Promote, Ignore, Reopen, the editor and note-box buttons), the agenda move/remove buttons, the "Done today" toggle, "Open ↗" links, the toast dismiss button, the toast action (Undo / Discard edits), the import preview's Include checkbox (an 18 px glyph inside a 40 px label, like the task checkbox), the quick-add Work/Personal toggle and the top tab links all have at least a 40 px tap target; the task title button has 6 px of hit area above and below its text (32 px for a one-line title).
- Toasts: at most four stack up, but a toast with a live Undo (tick, untick, drop) is never evicted to make room for a plain one; the SheetJS wait says "Preparing the spreadsheet…" and distinguishes "did not load" (script error) from "has not loaded yet" (15 s timeout) when it falls back to CSV.
- Theme: `color-scheme: light dark` on `:root` so native widgets follow the dark variant; `--danger-ink` gives the High chip and error toasts dark text on the pale dark-mode red.
- Navigation reads the hash through `google.script.url.getLocation` and writes it with `google.script.history.replace` when those exist (the page runs in Apps Script's sandboxed iframe), falling back to `location.hash` otherwise.
- Rendering uses `createElement` / `textContent` through a small `h(tag, attrs, children)` helper; no `innerHTML` with data. Links render only when `sanitiseLink` accepts them (trimmed, lower-cased, starting with `http://` or `https://`), always with `target="_blank" rel="noopener"`.
- Pure helpers live between `/* pure:start */` and `/* pure:end */` in `App.html` with no DOM access, so the Node harness can eval them: `esc`, `sanitiseLink`, date helpers (`formatDateLabel`, `formatDateLong`, `addDays`…), `groupTasks`, `matchesSearch`, `formulaGuard`, `csvFromRows`, `buildAgendaWorkbookRows`, `buildNewsletterWorkbookRows`, `agendaToText`, `parseImportText`, `previewRowsToText`. `parseImportHtml` sits just after the block because it needs `DOMParser`.
- Dates come from the server as `yyyy-MM-dd` strings; "today" is `getBootstrap().today` (Dubai), never the browser clock.

## Import preview and submission

The contract has no dry-run call, so the preview is parsed on the client with the same rules as SPEC.md section 6: `#` headings set the project, `[Work]` / `[Personal]` / `[W]` / `[P]` prefixes set the category, `- [x]` / `[x]` / ✓ / ✔ / ☑ mark done, bullets and `1.` / `1)` numbers are stripped, trailing `@2026-10-14` or `due: 2026-10-14` set the due date, trailing `!` or `!!` set High, lines whose title is two characters or fewer once those prefixes, marks and bullets are stripped are skipped (the same measure as the server's `Import.gs`). HTML files are parsed with `DOMParser` on a detached document (scripts and styles are removed and never run): `h1`–`h4` headings containing work/school/AISA or personal/home set the category (and clear the project), other headings set the project; `li` elements, checkbox inputs and elements whose class contains `task` or `todo` are items; a checked box, a done/completed/checked/line-through class, an inline `line-through` style or a `<s>`/`<del>` wrapper marks done; the first `<a href>` inside an item becomes its link; nested lists become their own items. With no items at all, the stripped text goes through the text rules.

The user edits the preview, then the included rows are turned back into text by `previewRowsToText` and sent in one `importText` call, in preview order so the sheet keeps the document's order: a `# Project` line is emitted whenever the project changes (a bare `#` clears it, which is how the server reads an empty heading), and each line is `[Work] [x] Title @2026-10-14 !` (category always explicit, `[x]` only when done, `@due` and `!` only when set). Rows that carry a link (HTML imports) are matched to the returned `added` tasks by normalised title in the form the server stores it (whitespace collapsed, trailing `!` marks removed, cut to 140 characters: `importTitleKey`) and get the link through `updateTask` afterwards, one call per link; the result card reports how many links were attached.

## Downloads

SheetJS 0.18.5 is loaded from cdnjs with the pinned `integrity` hash and an `onerror` that sets `window.__xlsxFailed`. The agenda workbook has one sheet `Agenda`: title rows (meeting date, window, director name when set), a blank row, then Section / Item / Detail / Link with real hyperlinks (`cell.l = {Target}`) and column widths (`ws['!cols']`). The newsletter workbook has one sheet `Newsletter` with Project / Item / Note / Status / Done / Link. Cells starting with `=`, `+`, `-` or `@` are prefixed with a space in both formats. The community SheetJS build cannot write cell styles, so the header row is plain text, not bold (SPEC section 8 and the README say so). When SheetJS is missing the same rows download as a UTF-8 CSV and a toast says so. Copy uses `navigator.clipboard.writeText` with a hidden-textarea `execCommand('copy')` fallback.

## Checks

- `npm test` runs the server unit tests (`tests/run.js`) and then `tests/e2e.js`: the assembled page in headless Chromium talking to the real `.gs` code (loaded into the `node:vm` sandbox over `tests/gas-mock.js`) through a `google.script.run` shim routed to `page.exposeFunction`. It seeds the mock sheet, drives quick-add, tick/undo, the inline editor (including keyboard focus), move, drop, promote/ignore/capture, the text import with every section 6 syntax, the agenda draft/save/regenerate, the `.xlsx` downloads (read back: one sheet, header row, hyperlinks, column widths), the newsletter and history, and asserts on both the DOM and the sheet rows at 1280×900 and 390×844, then once more at 1280×900 with the SheetJS CDN blocked so the CSV fallback runs; screenshots land under `/tmp/claude-0/brandons-desk-ui/e2e-screenshots/`, downloads under `.../e2e-downloads/`. It needs a Chromium: `npx playwright install chromium` once after `npm install`, or `CHROMIUM_PATH` (a pre-installed `/opt/pw-browsers/chromium` is used when present).
- `npm run ui` (`tests/ui/render.js`, see `tests/ui/README.md`): the same page against the fixture-backed `tests/ui/mock-server.js` shim, covering the UI-only paths (HTML file import, downloads read back, dark mode, SheetJS missing, boot failure); screenshots under `/tmp/claude-0/brandons-desk-ui/screenshots/`. `node tests/ui/assemble.js --mock` writes a standalone `index.mock.html` to open by hand.
