# Web UI

Single page served by `doGet()` from `apps-script/Index.html` (template: `<?!= include('Styles') ?>` in the head, `<?!= include('App') ?>` at the end). No framework, no build step; plain ES2019 JavaScript (no optional chaining or nullish coalescing) so Apps Script V8, older Safari and the Node test harness all run it. DM Sans from Google Fonts with a system fallback; tokens on `:root` (accent `#21076C`, highlight `#D8B664`, backgrounds `#FFFFFF` / `#F7F6FB`) with a `prefers-color-scheme: dark` variant. Mobile first from 360 px with 16 px gutters; the Tasks page is two columns from 840 px. The Desk page (below) has its own fonts and tokens, used only there.

## Components and conventions

- `api(name, payload)` is the only path to the server: a Promise around `google.script.run.withSuccessHandler().withFailureHandler()`. Every write shows a toast; failures show the server's message, roll back optimistic state and withdraw the optimistic success toast (tick, untick, drop). The first paint shows a loading state and keeps every page section hidden; a failed bootstrap shows only the error with Try again.
- Keyboard: opening the inline editor (Enter/click on a task title) moves focus into it; Save, Cancel and Escape return focus to the title; Move to the other list saves any unsaved editor edits first (one `updateTask`, then `moveTask`) and follows the task into its new column; Drop focuses the next task of the group (else quick-add) and sends only a note that was changed in the editor (the server appends notes); completing a task (Enter in the note box, Done, Done, no note) focuses the ticked row's checkbox when "Done today" is open (Space there is the keyboard undo), otherwise the next task of its group, otherwise quick-add; unticking and the toast's Undo focus the row's checkbox in its new group, also after the server reply re-renders the columns; Inbox Ignore focuses the next item's Promote button (else the status filter); History Reopen focuses the next item's Reopen button (else Apply); the promote form's Cancel returns to that item's Promote button; the agenda Move up / Move down / Remove buttons put focus back on the moved row's control after the sections re-render, and an agenda section's Add button focuses the new row's first field, so a keyboard or screen-reader user never drops to the top of the page; the Desk's *Full agenda* link moves focus to the Agenda tab (the link's own page is hidden then). The editor's six fields are `<label for>`-named controls. The quick-add category toggle is a `radiogroup` with `role="radio"` / `aria-checked` buttons. The "Done today" group remembers that it was opened across re-renders (search, quick-add, toast-driven updates).
- Touch: the task checkbox, source-link icon, every `.btn.small` action button (Promote, Ignore, Reopen, the editor and note-box buttons), the agenda move/remove buttons, the "Done today" toggle, "Open ↗" links, the toast dismiss button, the toast action (Undo / Discard edits / Reload agenda), the import preview's Include checkbox (an 18 px glyph inside a 40 px label, like the task checkbox), the quick-add Work/Personal toggle and the top tab links all have at least a 40 px tap target; the task title button has 6 px of hit area above and below its text (32 px for a one-line title).
- Toasts: at most four stack up, but a toast with a live Undo (tick, untick, drop) is never evicted to make room for a plain one; the SheetJS wait says "Preparing the spreadsheet…" and distinguishes "did not load" (script error) from "has not loaded yet" (15 s timeout) when it falls back to CSV.
- Theme: `color-scheme: light dark` on `:root` so native widgets follow the dark variant; `--danger-ink` gives the High chip and error toasts dark text on the pale dark-mode red.
- Navigation reads the hash through `google.script.url.getLocation` and writes it with `google.script.history.replace` when those exist (the page runs in Apps Script's sandboxed iframe), falling back to `location.hash` otherwise.
- Rendering uses `createElement` / `textContent` through a small `h(tag, attrs, children)` helper; no `innerHTML` with data. Links render only when `sanitiseLink` accepts them (trimmed, lower-cased, starting with `http://` or `https://`), always with `target="_blank" rel="noopener"`.
- Pure helpers live between `/* pure:start */` and `/* pure:end */` in `App.html` with no DOM access, so the Node harness can eval them: `esc`, `sanitiseLink`, date helpers (`formatDateLabel`, `formatDateLong`, `addDays`…), `groupTasks`, `matchesSearch`, `formulaGuard`, `csvFromRows`, `buildAgendaWorkbookRows`, `buildNewsletterWorkbookRows`, `agendaToText`, `agendaShowsWindow`, `normaliseAgenda`, `agendaSectionsForSave`, `isAgendaConflict`, `parseImportText`, `previewRowsToText`, and for the Desk `sanitiseStoredLink`, `expandDeskLink` / `deskHref`, `normaliseDesk`, `deskCategoryOf`, `deskLaneKey`, `deskCounts`, `deskTagClass`, `deskBuiltLine`, `deskStaleNote`, `deskYmd`, `deskAgendaToText`, `deskSavedAgendaSections`, `deskAgendaWorkbookRows`, `deskLltText`, `joinNote`. `parseImportHtml` sits just after the block because it needs `DOMParser`.
- Dates come from the server as `yyyy-MM-dd` strings; "today" is `getBootstrap().today` (Dubai), never the browser clock.

## The Desk page

Contract: `docs/DESK.md` section 3. The Desk is the first tab and the home page (`showPage` falls back to `desk` for no hash or an unknown one); the old Today tab is now **Tasks**, still at `#today`.

- **Data.** `getDesk` runs when the Desk is first shown (not during boot, so the other pages never wait for it). `normaliseDesk` gives every field a value of the right type, so a board with missing or malformed fields still renders: default lanes (Do today / Reply & follow up / This week) when `lanes` is missing, items in an unknown lane shown and counted in the first lane, an item without an id shown with its checkbox disabled, `agenda` / `llt` blocks only when present, empty sections with a one-line note. The `added` tasks join `state.tasks`, so the Desk and the Tasks page share one object per task.
- **Layout and look.** Ported from the routine's page: its colour tokens (`--dk-*`, light and dark), Bricolage Grotesque for headings, DM Sans for text, JetBrains Mono for eyebrows, tags and counts, and its breakpoints (lanes 1.25fr / 1fr / 1fr, the first lane over two columns up to 1000 px, one column up to 680 px; the strip scrolls sideways inside itself). Everything is scoped to `.desk` / `.dk-*` classes, and `body.on-desk` sets the page background, so the other pages are unchanged. On a desktop the Desk uses the routine page's 1240 px frame with 20 px gutters while the top bar keeps the app's 1120 px frame (widening the bar only on the Desk would make the tabs jump on every page switch). Differences from the routine's page, on purpose: the app's top bar and tabs above it; the Work/Personal toggle in the add box (after Add, in the same order for the keyboard; on a phone it wraps under the input and Add); a 40 px tap target on every checkbox (a 40 x 40 label round the 20 px box), button and toggle, and a transparent 40 px hit area on each link pill, each Coming up title link and the footer's Desk page link, and a 40 px agenda toggle; no Rebuild now button (the footer's *Open the Desk page* link goes to the routine's page, which has it); the meter's line says ticks save to the tracker.
- **Cards and links.** Tags are mono chips with the routine's colour meanings (`late` red, `due` amber, `new` blue, `home` green, `gh` grey, `list` gold, a source tag such as Email in the accent colour); the class comes from a whitelist (`deskTagClass`). Link targets go through `deskHref` = `expandDeskLink` (`wt:` / `w:` / `p:` to Gmail URLs, then the server's `sanitiseLink` rule via `sanitiseStoredLink`; identical to the server's `expandDeskLink` for every input, which `tests/desk.test.js` checks); a target it refuses is shown as its label in plain text. The same applies to strip days, Coming up titles, quick links and the padlet link. All text goes in with `textContent`.
- **Ticks.** A board item ticks optimistically (card dims and strikes through, meter and lane counts update, the meter line says "Saving to your tracker…"), then `setDeskItemDone({itemId, done})`; the task it returns joins `state.tasks`, so the Tasks page shows it at once. An "Added by you" task ticks through `completeTask` / `reopenTask`. Clicks on one card are queued, so a quick tick-untick reaches the server in order. On failure the card goes back to its last confirmed state, the optimistic "Done:" toast is withdrawn and the error toast shows. Coming back to the Desk re-renders it from `state.tasks`, so ticks made on the Tasks page show there too.
- **Note after a tick.** A ticked card opens a one-line note field (not focused, so ticking on a phone does not pop up the keyboard). Enter or *Save note* sends `updateTask` with `patch.note` = the row's note joined with the new one (`joinNote`, the server's " · " rule, since `updateTask` replaces the cell); the call waits in the card's queue behind the tick. Escape or × closes it; focus returns to the card's checkbox.
- **Added by you.** Open Manual tasks that are no board item's task, at the top of the first lane with an "Added by you" chip (and Personal when they are): those `getDesk` listed, tasks added in the Desk's add box or the Tasks page quick-add (newest first), and any other such task in `state.tasks` (a Manual task reopened from History) while fewer than 20 listed tasks are open. At most 20 listed tasks are open at once, the cap `getDesk` uses: past it the oldest open ones (by Created, Updated, ID) wait off the list until there is room. A listed task stays, ticked, after it is done. A board item whose row is dropped on the Tasks page shows ticked (getDesk reads Dropped as done), and one whose row is moved to the other list follows the copy.
- **Add box.** `addTask({category, title})`, Work by default; a pending card shows at once; a duplicate gets the "Already on your list" toast and no card; a failure restores the title. The form node is kept across re-renders, so typing and focus survive a tick reply arriving.
- **Agenda.** Open when `agenda.open`; a toggle is remembered across re-renders; the title is `agenda.title`. When `agenda.meeting` is a date (`normaliseDesk` keeps it only then), `getAgenda({meetingDate})` runs after the Desk loads and on every visit; only the agenda block is swapped when it answers (`renderDeskAgenda`, focus kept by id), so ticks, notes and the add box are never disturbed, and an answer for an older request or another meeting is dropped. With `saved: true` the block shows the sheet's rows (`deskSavedAgendaSections`): Done, In progress, Decisions & questions and, when there are any, Documents as link pills (two columns by two from 901 to 1180 px, four above); Notes are not shown. *Copy agenda as text* and *Download .xlsx* then use `agendaToText` / `buildAgendaWorkbookRows` on that agenda (the Agenda page's text and file, `agenda-<meeting date>`). Otherwise (no meeting, not saved, a failed read) they use the Desk JSON: the routine page's text format (`deskAgendaToText`) and one sheet "Agenda" with the agenda title, "Director: <DIRECTOR_NAME>" when set, a blank row, then Section / Item / Detail, formula-guarded, file `desk-agenda-<build date>`; both through the existing `downloadWorkbook` (SheetJS, else CSV). *Full agenda* (a link with a 40 px hit area) opens the Agenda page at the meeting's date (`openAgendaAt`): unsaved edits of another week stay and the *Discard edits* toast asks first.
- **States.** `reason:"empty"`: a panel "Your Desk appears here after the next morning build (6:45 on school days), or press Rebuild now on the Desk page." with the Desk page link, and one lane with the add box and the added tasks. `reason:"invalid"`: the server's message, the link and the same lane. `getDesk` failing: the error with *Try again*. `stale`: a highlighted footer note "This Desk is from <weekday d Mon>; the next build is at 6:45 on school days." with the link.
- **Focus.** `renderDesk` rebuilds the board; the focused control is found again afterwards (the same role in the card with the same key, else that card's checkbox).

## The Agenda page

Contract: `docs/AGENDA.md` section 2.

- **Provenance.** Each row keeps the `generated` the server sent (`normaliseAgenda`) and sends it back with Save (`agendaSectionsForSave`). Typing in a row's Item, Detail or link clears its `generated` (the line becomes Brandon's); a row added with an Add button starts with `''`; moving or removing rows leaves every other row's `generated` alone. The server decides column H from it (a tag is written back, `web-draft` is stamped, anything else is the save time). A row whose text is empty is left out of the save, even when it carries a task link; only a Documents row typed as a bare link keeps the link as its name.
- **Re-reading.** `loadPage('agenda')` calls `loadAgenda` with the shown meeting date (or the one the Desk's *Full agenda* asked for) whenever there are no unsaved edits and no save or regenerate on its way (a reload would overtake its answer). Every load uses up the date *Full agenda* asked for, so it never returns on a later visit; when the page keeps its week (unsaved edits of that week, or a save or regenerate on its way), *Full agenda* for the same week leaves it as it is and for another week loads it at once, as the date picker does. Every read and regenerate is numbered and only the latest answer is shown, so a reload overtaken by Regenerate or another week never lands on top of it; the date picker and *Discard edits* still overtake a regenerate on its way. Regenerate marks the agenda as edited.
- **Stale saves.** The page stores the `stamp` from `getAgenda` / `regenerateAgenda`, sends it with `saveAgenda` and keeps the one the save returns, so a second save needs no reload. When the server refuses the save because the week changed (`isAgendaConflict`), the error toast stays up for a minute with *Reload agenda*, which drops the edits and reads that meeting date again; until then the edits stay on the page (and *Copy as text* copies them). Edits typed while a save is on its way stay on the page, unsaved.
- **Window.** The page header, the `.xlsx` and Copy as text show "Window: …" only for an unsaved draft (`agendaShowsWindow`): a saved agenda may cover more than the week before the meeting.

## Import preview and submission

The contract has no dry-run call, so the preview is parsed on the client with the same rules as SPEC.md section 6: `#` headings set the project, `[Work]` / `[Personal]` / `[W]` / `[P]` prefixes set the category, `- [x]` / `[x]` / ✓ / ✔ / ☑ mark done, bullets and `1.` / `1)` numbers are stripped, trailing `@2026-10-14` or `due: 2026-10-14` set the due date, trailing `!` or `!!` set High, lines whose title is two characters or fewer once those prefixes, marks and bullets are stripped are skipped (the same measure as the server's `Import.gs`). HTML files are parsed with `DOMParser` on a detached document (scripts and styles are removed and never run): `h1`–`h4` headings containing work/school/AISA or personal/home set the category (and clear the project), other headings set the project; `li` elements, checkbox inputs and elements whose class contains `task` or `todo` are items; a checked box, a done/completed/checked/line-through class, an inline `line-through` style or a `<s>`/`<del>` wrapper marks done; the first `<a href>` inside an item becomes its link; nested lists become their own items. With no items at all, the stripped text goes through the text rules.

The user edits the preview, then the included rows are turned back into text by `previewRowsToText` and sent in one `importText` call, in preview order so the sheet keeps the document's order: a `# Project` line is emitted whenever the project changes (a bare `#` clears it, which is how the server reads an empty heading), and each line is `[Work] [x] Title @2026-10-14 !` (category always explicit, `[x]` only when done, `@due` and `!` only when set). Rows that carry a link (HTML imports) are matched to the returned `added` tasks by normalised title in the form the server stores it (whitespace collapsed, trailing `!` marks removed, cut to 140 characters: `importTitleKey`) and get the link through `updateTask` afterwards, one call per link; the result card reports how many links were attached.

## Downloads

SheetJS 0.18.5 is loaded from cdnjs with the pinned `integrity` hash and an `onerror` that sets `window.__xlsxFailed`. The agenda workbook has one sheet `Agenda`: title rows (meeting date, the window for an unsaved draft, director name when set), a blank row, then Section / Item / Detail / Link with real hyperlinks (`cell.l = {Target}`) and column widths (`ws['!cols']`). The newsletter workbook has one sheet `Newsletter` with Project / Item / Note / Status / Done / Link. Cells starting with `=`, `+`, `-` or `@` are prefixed with a space in both formats. The community SheetJS build cannot write cell styles, so the header row is plain text, not bold (SPEC section 8 and the README say so). When SheetJS is missing the same rows download as a UTF-8 CSV and a toast says so. Copy uses `navigator.clipboard.writeText` with a hidden-textarea `execCommand('copy')` fallback.
